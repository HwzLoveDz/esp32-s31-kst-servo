# 功能覆盖与实机验收

本项目把《KST 舵机 CAN 总线通信协议（扩展帧）V3.61B》中的运行、查询与参数配置命令接到 Korvo 自带触摸屏。下表说明软件覆盖范围和逐项验证方法；已经完成的只读通信、运动与恢复结果见 [VALIDATION.md](VALIDATION.md)。接线与版本条件见 [HARDWARE.md](HARDWARE.md)。

FUI 为 800 × 480，底部五个页面分别是 `MONITOR`（监测）、`MOTION`（运动）、`SERVICE`（参数/维护）、`LINK`（通信）、`LOG`（日志）。`SERVICE` 内容可上下滚动。界面输入框是准备下发的值；标为 `READBACK` 的数据才来自已解析的舵机回复。

## 1. 三层接口

| 层 | 位置 | 责任 |
| --- | --- | --- |
| 帧编解码 | `components/kst_protocol` | `kst_make_*` 构造扩展帧；`kst_parse` 严格解析接收帧；不直接碰硬件 |
| 单舵机事务 | `components/kst_servo` | `kst_servo_*` 串行发送请求、匹配回复、处理超时/ABORT；位置和 SAVE 不伪造应用 ACK |
| 板端适配与屏幕 | `components/kst_usb_gs`、`components/kst_twai`、`main` | 默认 USB-CAN、可选 TWAI 收发，单任务持有 CAN 客户端、动作队列、LVGL FUI 与真实读回状态 |

`kst_servo_*` 必须由同一个任务调用，不能从触摸回调直接阻塞调用；FUI 使用 `app_submit()` 投递操作。节点范围为 1～127。库中的厂家通用默认值为37 / 500 kbit/s；本项目当前连接实测设备，默认 **5 / 1 Mbit/s**。通用库拒绝广播节点0；可选诊断有唯一的广播只读节点查询。

实物版本3.66返回功能字 `0x5C90`，高字节与V3.61B 协议不同。现已兼容读取并保留完整原值；高字节含义和写格式未确认时，库拒绝修改功能字，SERVICE 的 SET REV / SET ALARM 禁用并显示原因。这两项仍需新版协议支持，不能以软件入口存在视为实物支持已验证。

## 2. V3.61B 逐项覆盖

下面的“成功判据”区分 CAN 传输完成、舵机应用回复、读回和机构动作。写 ACK 只证明舵机应用接受了该配置请求，不自动证明已持久化或实际运动完成。

| 协议项 / 页码 | 底层构帧或解析 API | 事务 API | FUI 入口 | 成功判据与验收方法 |
| --- | --- | --- | --- | --- |
| 2.1 启动上报 / p3 | `kst_make_reporting(..., true, ...)` | `kst_servo_set_reporting(..., true)` | SERVICE → START REPORT | 等待一个新的有效 `POSITION_REPORT`；观察接收计数和位置数据时间。没有专用启动写 ACK |
| 2.2 停止上报 / p3 | `kst_make_reporting(..., false, ...)` | `kst_servo_set_reporting(..., false)` | SERVICE → STOP REPORT | 返回“已发出、未确认”；独立抓包确认自动上报停止。页面仍可能因主动读位置而更新，不能只看画面是否停住 |
| 2.3 自动上报格式 / p3 | `kst_parse` → `KST_EVENT_POSITION_REPORT` | 事务中的事件回调或 `kst_servo_poll` | MONITOR / LOG | 识别 DLC=4 的位置上报；与 DLC=8 的查询回复区分；角度单位 0.1°。REV=1 时只把自动上报视为接收活动，角度继续由显式查询更新，避免假设未说明的上报符号规则 |
| 2.4 低压报警 / p3 | `kst_parse` → `KST_EVENT_UNDERVOLTAGE` | 事件回调或 `kst_servo_poll` | LOG 报警提示 | 真实收到报警帧后本地锁存提示；清除本地提示不修改设备报警功能。无报警不证明供电合格 |
| 2.5 设置上报间隔 / p4 | `kst_make_report_interval` | `kst_servo_set_report_interval` | SERVICE → INTERVAL → SET INTERVAL | 10～255 ms，等待写 ACK；开启上报后抓包测间隔。立即生效，SAVE 后才持久化；协议没有单独读间隔命令 |
| 2.6 设置波特率 / p4 | `kst_make_baudrate`、`kst_baudrate_bps` | `kst_servo_set_baudrate` | LINK 右侧 → NEW BITRATE → SET BAUD | 在旧波特率收到写 ACK；SAVE、舵机重启后才切换。再在 LINK 左侧选择新波特率并 CONNECT，通过读回确认通信 |
| 2.7 设置节点 / p4 | `kst_make_node_id` | `kst_servo_set_node_id` | LINK 右侧 → NEW NODE → SET NODE | 在当前地址收到写 ACK；SAVE、舵机重启后生效；LINK 左侧改为新地址并 CONNECT，再 READ NODE |
| 2.8 位置设置 / p5 | `kst_make_position` | `kst_servo_set_position` | MOTION → ARM MOTION → SEND POSITION；START SWEEP 也使用此命令 | **成功没有应用 ACK**；发送完成后另外读取实际角度，并观察真实机构。目标还受当前舵机限位和主机检查限制 |
| 2.9 设置中点 / p5 | `kst_make_center` | `kst_servo_set_center` | SERVICE → SET CURRENT AS CENTER → 确认 | 将当前位置定义为中点，写 ACK 后读位置确认零点变化；立即生效，SAVE 后持久化。属于校准操作，示例只允许当前反馈在 ±10° 内进行微调 |
| 2.10 保存参数 / p5 | `kst_make_save` | `kst_servo_save` | SERVICE / LINK → SAVE PARAMETERS → 确认 | **没有应用 ACK**，不能显示“保存已验证”；保存所有已修改参数。重启后读回可读参数验证，协议未给保存完成等待时长 |
| 2.11 读节点号 / p5 | `kst_make_read_node` | `kst_servo_read_node` | SERVICE → READ NODE / ALL READBACK | 收到匹配索引的 `NODE_ID`，核对与所连接节点一致 |
| 2.12 读位置 / p6 | `kst_make_read_position` | `kst_servo_read_position` | MONITOR → READ POSITION；SERVICE → ALL READBACK | 解析 `POSITION`；与外部角度观测比较。0.1° 是协议刻度，不是机械精度保证 |
| 2.13 读状态 / p6 | `kst_make_read_status` | `kst_servo_read_status` | MONITOR → READ STATUS；SERVICE → ALL READBACK | 解析电流与温度；电流单位 10 mA、温度单位 1°C；画面显示本次读回及年龄。这里没有精确供电电压、扭矩或速度读数 |
| 2.14 读取功能位 / p6～7 | `kst_make_read_features` | `kst_servo_read_features` | SERVICE → READ FLAGS / ALL READBACK | 读取并保留完整功能原值，显示十六进制值与已知低字节功能位 |
| 2.14 设置低压报警功能 / p6～7 | `kst_make_features` | `kst_servo_set_features` | SERVICE → LOW-VOLTAGE ALARM → SET ALARM | 仅在功能字格式受支持时可写；实测 0x5C90 保持只读。先读原值，仅修改 bit5 `0x20`、保留其它位，写 ACK 后读回校验；立即生效，SAVE 后持久化 |
| 2.14.1 逻辑反向 / p7 | `kst_make_features` | `kst_servo_set_features` | SERVICE → FEEDBACK REVERSE → SET REV | 仅在功能字格式受支持时可写；实测 0x5C90 保持只读。同样按读改写与读回验证，仅修改 bit6 `0x40`；文档描述的是**位置反馈符号**，不能当作机械旋转方向或命令极性切换。FUI 将反馈按该位换算回命令轴坐标，检查原始符号变化需抓包 |
| 2.15.1 设置负向范围 / p7 | `kst_make_limit(..., false, ...)` | `kst_servo_set_limit(..., false, ...)` | SERVICE → NEGATIVE LIMIT → SET MIN | 写 ACK 后标记待保存/重启；范围 -100.0°～0.0°。SAVE、重启后 READ LIMITS，确认实际生效 |
| 2.15.2 设置正向范围 / p8 | `kst_make_limit(..., true, ...)` | `kst_servo_set_limit(..., true, ...)` | SERVICE → POSITIVE LIMIT → SET MAX | 写 ACK 后标记待保存/重启；范围 0.0°～100.0°。SAVE、重启后 READ LIMITS，确认实际生效 |
| 2.16.1 读负向范围 / p8 | `kst_make_read_limit(..., false, ...)` | `kst_servo_read_limit(..., false, ...)` | SERVICE → READ LIMITS / ALL READBACK | 解析 `LIMIT_NEGATIVE`；将读回值与已记录基线及拟设值比较 |
| 2.16.2 读正向范围 / p8 | `kst_make_read_limit(..., true, ...)` | `kst_servo_read_limit(..., true, ...)` | SERVICE → READ LIMITS / ALL READBACK | 解析 `LIMIT_POSITIVE`；必须与负向范围一起确认，不只检查单端 |
| 2.17 读软件版本 / p8 | `kst_make_read_version` | `kst_servo_read_version` | SERVICE → READ VERSION / ALL READBACK | 显示协议返回的四个版本字节；这是设备查询结果，不代表完成固件升级 |
| 2.18 读写失败与附录1 / p9～10 | `kst_parse` → `KST_EVENT_ABORT`；`kst_abort_description` | 事务返回 `KST_SERVO_ERR_ABORT` 并保留对象索引、错误码 | LOG / 页面底部操作结果 | 核对错误码与所请求对象；超时、ABORT 和发送错误要分别记录，不把未收到回复当作成功 |
| 附录2 CAN 接线 / p11 | 非命令 | `kst_twai_open` / `kst_twai_reopen` | LINK / LOG | 依 HARDWARE 接线，确认扩展帧、波特率、节点和两端终端，再验证真实收发 |
| 附录3 通讯端口升级 / p11 | **未实现** | **无升级 API** | SERVICE → FIRMWARE SERVICE BOUNDARY | 附录仅引用另一本《通讯端口升级软件说明》，缺少升级帧、流程及适配镜像。当前资料不足以实现可靠升级，不能根据版本查询推测升级协议 |

协议勘误：文档第 5 页 `+50°` 示例的 `01 FC` 等于 50.8°，与文档声明的单位矛盾。本例按明确的 0.1° 单位编码：`+50° → 500 → 01 F4`。详见 [协议库说明](../components/kst_protocol/README.md)。

## 3. 主机附加功能与边界

位置**反馈**现单独允许 −180.0°～+180.0°，目标和普通限位写入仍按已知协议限制在 ±100.0°。
实物曾回报 −100.5°；不能因为反馈越过目标范围就丢弃它，否则会误判数据过期并阻断返回。
MOTION 显示 `OUTSIDE TARGET LIMITS`，`SELECT NEAREST LIMIT` 只把合法边界填入目标，
用户仍需 ARM、SEND 才下发。也可将目标微调到范围内。越界时禁止启动 SWEEP；
已有 ABORT 需先在 LOG 清除本地提示，再检查新反馈并解锁。

`CONFIG_KST_PROBE_360_ON_START` 是默认关闭的临时兼容性诊断，普通发布版不启用。
它只对节点5/版本3.66且完整新鲜读回、当前位置合法的设备，逐侧试写 ±180°限位并恢复原值；
不发位置目标、CENTER、功能修改或 SAVE。每次启动只判断一次；条件不足即 SKIP。
每次尝试写候选值后都显式恢复并核验；USB换代后不跨连接写回。无法核验时锁住运动和参数写入，
包括 SAVE；CLEAR/RECONNECT 不解锁。该锁是本次运行期状态，不能用重启当作已恢复证明。
单侧参数接受不证明两端组合、重启生效或360°机械行程，必须分别验证。

当前实物结论：3.66 对+180°写入返回 `80 0B 30 00 06 09 00 30`，即拒绝；
随后恢复+100°获ACK并读回确认，负端未试写。当前可用目标仍为−100°～+100°。
越界后手动返回合法范围已由实物操作确认。详细帧记录见 [VALIDATION.md](VALIDATION.md)。

| 操作 | 实际作用 | 不能据此推断 |
| --- | --- | --- |
| 上电/启动 | 初始化界面、总线并只读查询；不自动设置目标位置、校准、SAVE 或启动扫动 | 舵机自身固件可能在上电时移动，软件不发运动命令不等于机械绝对静止 |
| ARM MOTION | 允许本控制台发送位置命令 | 不是舵机电机使能，也不是接触器或独立硬件保护 |
| 滑条、角度预设、数字 +/− | 编辑待发送目标；另按 SEND POSITION 才下发 | 拖动输入值不代表实际角度已经变化 |
| START SWEEP | 主机按设定幅度/时长完成一轮有限轨迹：当前反馈位置 → 0 → +幅度 → -幅度 → 0，然后停止继续发轨迹目标 | 不是无限循环，也不是舵机内部速度环或轨迹模式；实际速度与负载有关 |
| PAUSE TEST / DISARM MOTION | 停止继续发送新的运动目标并撤销本机运动许可 | **不能撤回已接收目标、不能放力、不能保证立即停转，也不是硬急停** |
| CONNECT / RECONNECT（LINK 左侧） | 改本机通信地址/波特率并重新查询 | 不会改写舵机地址、波特率或自动 SAVE |
| RECOVER CAN BUS | 显式重新创建本机 CAN 控制器，重新接入 | 不自动恢复扫动或重放超时的位置目标；需要重新确认读回和 ARM |
| CLEAR LOCAL ALERTS | 清除本机记录的报警提示 | 不修复低压、不清舵机内部故障、不证明故障原因消失 |
| MONITOR 曲线 | 用收到的角度反馈采样显示趋势，标出过期数据 | 不是轨迹跟踪精度测试，也不是带精确时间同步的 CAN 抓包仪 |
| 主机运动范围 | 本次 Korvo 运行期间取已读回/已要求收紧的最保守范围；重连不会自行放宽 | 参数写 ACK 或读到更宽拟设值不证明舵机已经重启并启用该范围 |

V3.61B 协议没有放力/扭矩关闭、硬急停、目标扭矩、速度目标、阻抗控制或连续多圈旋转命令。本例不添加含义不明的“停机帧”，不把读取电流称为力矩控制。需要可靠切断驱动力时，应使用与实际机构相适应的外部电源断开方式。

## 4. 分步实机验收

每步保留实际观察或日志；不以编译通过、预览截图、TX 计数增加代替实机结果。建议记录舵机完整型号/软件版本、Korvo 板版本、隔离模块型号、线束和供电配置。

### A. 通电与只读通信

1. 按 [HARDWARE.md](HARDWARE.md) 接线：默认 USB-CAN 路径保留摄像头；只有选择 TWAI 并复用 J4 GPIO46/47 时才拔下摄像头。保持 LCD/触摸接好、舵臂有自由活动空间，记录供电和机械位置。
2. 启动 Korvo，确认五个标签都可点击、SERVICE 可滚动、屏幕没有因 CAN 超时冻结。未读取到的数据应显示 `--`，旧数据应显示 `STALE`，不应凭空生成实时值。
3. 应用默认连接节点 5（0x05）、1000000 bit/s。另一只舵机若使用厂家通用默认 37（0x25）/500000 bit/s 或其它配置，在 LINK 左侧填写实际值再按 CONNECT。收到正确节点的合法回复后才判定通信可用。
4. 执行 ALL READBACK，分别记录节点、软件版本、功能字节、负向/正向范围、角度、电流和温度。任何查询失败均保留失败项，不填猜测值。
5. 用 CAN 分析仪或其它独立抓包设备检查启动阶段只有读请求，没有位置目标、设中点、参数写入、SAVE 或自动扫动命令。若无独立抓包设备，这项标为未独立验证。

### B. 首次小角度运动

1. 确认位置、状态和两端限位已经读回，未出现 CAN 错误或低压报警；先以当前已知位置附近的小角度为目标，避免直接测试全行程。
2. 只编辑滑条/预设，确认输入变化时没有运动命令被发出。再按 ARM MOTION、SEND POSITION。
3. 记录“命令已发出但无应用 ACK”、随后的实际角度读回，以及肉眼/外部角度测量。三者分开记录；CAN 层成功不能代替“到位”。
4. 再做一次方向相反的小角度动作，确认连杆运动方向与读数。外部角度误差评价要事先选容差和测量方法，不能用协议 0.1° 刻度当容差。
5. 使用很小幅度和较慢周期启动扫动，点击 PAUSE TEST，确认后续位置目标停止发送。已在执行的目标可能继续完成并保持扭矩；不要通过徒手强行转动舵臂验证“停止”。

### C. 上报与反馈

1. 设上报间隔为 100 ms，收到写 ACK 后 START REPORT，确认真实位置上报出现；再用抓包比较不同合法间隔的变化。
2. STOP REPORT 后确认没有声称收到应用 ACK。用抓包区分 DLC=4 自动上报和主动位置查询回复，验证自动流是否停止；控制台仍主动查询时画面更新是正常现象。
3. 比较空载静止和轻微运动时的电流/温度反馈；需要定量验收时使用外部仪表，并记录采样方式和误差。不要制造堵转来验证最大电流。
4. 无法在允许供电范围内安全触发真实低压报警时，保持该项未实测。可用台架报文注入验证解析与界面，但必须记录为“注入帧测试”，不能写成舵机欠压保护实测。

### D. 配置、保存与重启

1. 先保存 A 阶段读出的配置基线。每次只修改一个参数，并记录旧值、请求值、ACK、读回和是否需要重启。
2. 仅在功能字格式符合已知协议、SET REV / SET ALARM 可用时测试功能写入。当前 3.66 实物返回 0x5C90，两个写入入口保持禁用。对于受支持的设备，确认事务执行读改写并保留其它位。检验反向功能时比较原始 CAN 反馈符号，不直接假定物理方向改变；FUI 会根据反向位把角度还原为命令轴坐标，因此画面角度不一定翻转。验证后按需求恢复基线。
3. 正负限位只在机构允许范围内测试：写入 → SAVE → 等待实际设备完成参数写入 → 舵机断电重启 → READ LIMITS。协议没有给出 SAVE 完成等待时间，不编造一个保证安全的固定毫秒数；按厂商要求或实测确定。主机限制在同次 Korvo 运行中只收紧；需要使用扩大后的范围或改接其它舵机时，先确认舵机配置已生效，再重启 Korvo 并重新只读确认两端范围。
4. 设中点会立即改变角度基准，仅在确有校准需求、当前位置和基线已记录时测试；确认对话框后读回验证，再按需求保存。不要把它作为普通回零按钮。
5. 改节点时先用当前地址 SET NODE 并收到 ACK，再 SAVE、重启舵机，最后在 LINK 左侧填写新地址 CONNECT、READ NODE。改波特率流程相同，重启后本机改用新波特率。修改前记录新旧设置，避免误以为重启后无响应是硬件损坏。
6. SAVE 成功下发的结果保持“未确认”；仅在重启后对应可读参数仍与目标一致时，记录该参数“持久化已验证”。上报间隔没有读命令，应重启后开启上报并抓包验证实际间隔。

### E. 断线与恢复

1. 在空载、低风险姿态并停止自动扫动后断开舵机电源，观察查询超时、数据过期、运动许可撤销和界面仍可操作。控制器收到过一次回复不应永久显示连接健康。
2. 需要验证扫动中的故障路径时，先确保机构允许停留在最后目标；记录断线后不再发出新目标，恢复连接后也不会自动续跑。
3. 排除接线、供电、波特率和终端问题后，手动 RECONNECT 或 RECOVER CAN BUS。确认不会重放超时前排队的位置目标；读回恢复后再由操作者 ARM。
4. 出现 ABORT 时保留十六进制错误码、对象索引及操作，不用自动重复配置写入掩盖错误。协议没有请求序列号，同对象超时后的迟到回复不能完全消除歧义；此项属于协议限制。
